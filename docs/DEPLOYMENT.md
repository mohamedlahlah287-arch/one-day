# دليل النشر (Deployment Guide) - Railway

النظام يتكون من **3 عمليات (بوتات) منفصلة**، وكلها تشترك في نفس الكود ونفس قاعدة بيانات Firestore:

| البوت | الملف | المنصة | من يستعمله |
|---|---|---|---|
| بوت التاجر | `src/bots/adminBot.js` | Telegram | كل صاحب متجر يدير منتجاته/طلباته |
| بوت السوبر أدمن | `src/bots/superAdminBot.js` | Telegram | أنت فقط - إضافة/حذف/إيقاف المتاجر وتغيير باقاتها. هنا أيضًا يعمل المجدول (cron) |
| بوت الزبائن | `src/bots/customerBot.js` | **Facebook Messenger** | زبائن كل المتاجر (صفحة واحدة تخدم الجميع عبر رابط `m.me/الصفحة?ref=storeId`) |

⚠️ **فرق مهم**: بوتا التاجر والسوبر أدمن يشتغلان بـ long polling عادي (بلا حاجة لرابط عام).
بوت الزبائن يشتغل كسيرفر HTTP (Express) يستقبل webhook من فيسبوك، ولازم له **رابط HTTPS عام**
(Railway يوفر هذا تلقائيًا عبر "Public Domain").

## خدمة واحدة أو 3 خدمات؟

عندك خياران:

- **3 خدمات منفصلة** (موصى به للإنتاج) — كل بوت في خدمة Railway خاصة به. لو صار مشكل فـ بوت
  الزبائن (حمل عالي، bug)، بوت التاجر والسوبر أدمن يبقيان يشتغلان عاديًا. هذا الدليل يشرحه بالتفصيل تحت.
- **خدمة واحدة فقط** (أرخص وأبسط، مناسب للبداية) — البوتات الثلاثة تشتغل فـ نفس الـ process عبر
  `npm start` (يشغّل `src/allInOne.js`). خدمة Railway وحدة، متغيرات بيئة مرة وحدة، Public Domain
  وحدة. المقايضة: لو صار خطأ غير متوقع فـ بوت واحد يوقف العملية كاملة، البوتات الثلاثة يتوقفو مع
  بعض لحد ما Railway يعيد التشغيل تلقائيًا (فعّل "Restart on Failure" حتمًا فهاذ الحالة).

لو اخترت **خدمة واحدة**: أنشئ خدمة Railway وحدة بـ Start Command = `npm start`، فعّل لها
Public Domain (نفس الخطوة تاع بوت الزبائن تحت)، وحط فيها **كل** متغيرات البيئة (Telegram +
Facebook + Firebase + Groq) مجتمعة فـ نفس الخدمة. باقي الدليل تحت مكتوب للخيار الأول (3 خدمات)
لكن يمديك تطبقه بنفس المنطق على خدمة وحدة.

## الخطوة 1: رفع المشروع إلى GitHub

من جهازك (وليس من هذه المحادثة، لأن هذه البيئة بلا اتصال إنترنت):

```bash
cd smart-seller-bot
git init
git add .
git commit -m "Initial commit - Smart Seller Bot"
git branch -M main
git remote add origin https://github.com/<اسمك>/smart-seller-bot.git
git push -u origin main
```

تأكد أن `.env` **غير موجود** في الملفات المرفوعة (تحقق من `.gitignore` — موجود بالفعل ويستثنيه).
لا ترفع أبدًا التوكنات أو مفاتيح Firebase مباشرة في الكود أو في GitHub.

## الخطوة 2: إنشاء 3 خدمات (Services) على Railway

في نفس مشروع Railway، أنشئ **3 خدمات منفصلة**، وكل خدمة تُربط بنفس مستودع GitHub لكن بأمر تشغيل مختلف
(من Settings → Deploy → Custom Start Command):

1. **Service: merchant-bot** → Start Command: `npm run start:merchant`
2. **Service: superadmin-bot** → Start Command: `npm run start:superadmin`
3. **Service: customer-bot** → Start Command: `npm run start:customer`
   → من Settings → Networking → **Generate Domain** (فقط لهاذي الخدمة، الوحيدة التي تحتاج رابط عام)

## الخطوة 3: متغيرات البيئة (Environment Variables)

في **كل خدمة من الثلاثة**، أضف نفس المتغيرات التالية (من Railway → Variables). الأسهل: أضفها مرة واحدة
كـ "Shared Variables" على مستوى المشروع إذا كانت نسختك من Railway تدعم ذلك، وإلا كررها في كل خدمة:

```
NODE_ENV=production
TELEGRAM_MERCHANT_BOT_TOKEN=<توكن بوت التاجر من BotFather>
TELEGRAM_SUPERADMIN_BOT_TOKEN=<توكن بوت السوبر أدمن من BotFather>
FB_PAGE_ACCESS_TOKEN=<من Meta for Developers - راجع FACEBOOK_SETUP.md>
FB_VERIFY_TOKEN=<تختاره أنت بنفسك>
FB_APP_SECRET=<اختياري لكن موصى به - من App Settings>
FB_PAGE_USERNAME=<اسم مستخدم صفحتك بدون @>
FIREBASE_PROJECT_ID=<من Firebase Console>
FIREBASE_CLIENT_EMAIL=<من ملف Service Account JSON>
FIREBASE_PRIVATE_KEY=<من ملف Service Account JSON - انسخها بين علامتي تنصيص>
SUPER_ADMIN_TELEGRAM_ID=<رقمك الشخصي على Telegram>
GROQ_API_KEY=<اختياري - لتفعيل الرد الصوتي وتحليل الصور>
LOG_LEVEL=info
RATE_LIMIT_WINDOW_MS=10000
RATE_LIMIT_MAX=15
```

⚠️ **ملاحظة مهمة عن `FIREBASE_PRIVATE_KEY`**: الملف الأصلي من Firebase يحتوي على أسطر جديدة حقيقية.
عند لصقها في Railway كمتغير بيئة، إذا صارت مشاكل اتصال بـ Firestore، جرب لصقها كسطر واحد مع `\n` مكتوبة
حرفيًا (الكود في `src/config/env.js` يحولها تلقائيًا لأسطر حقيقية).

`PORT` لا تحتاج تضيفه يدويًا - Railway يوفره تلقائيًا لخدمة `customer-bot` وسيرفر Express يقرأه لوحده.

## الخطوة 4: أنشئ بوتات Telegram (لبوت التاجر والسوبر أدمن فقط)

1. تحدث مع [@BotFather](https://t.me/BotFather) وأرسل `/newbot` مرتين لإنشاء:
   - بوت التاجر (مثال: `@MyStoreMerchantBot`)
   - بوت السوبر أدمن (مثال: `@MyStoreAdminBot`) - **لا تشاركه مع أحد**
2. انسخ كل توكن لمكانه الصحيح في متغيرات البيئة أعلاه

بوت الزبائن (Facebook) يحتاج خطوات إعداد مختلفة تمامًا - راجع
**[docs/FACEBOOK_SETUP.md](./FACEBOOK_SETUP.md)** (لازم تشغّل خدمة `customer-bot` على Railway
وتفعّل لها Public Domain **قبل** ما تقدر تربط webhook فيسبوك، لأن فيسبوك يحتاج يتأكد من الرابط
وهو شغال فعليًا).

## الخطوة 5: تفعيل "Restart on Failure"

في إعدادات كل خدمة على Railway، فعّل "Restart Policy: On Failure" حتى لو صار انقطاع مؤقت
(مشكلة شبكة، إلخ) يعيد Railway تشغيل البوت تلقائيًا بلا تدخل منك.

## بعد النشر مباشرة - أول استعمال

1. افتح بوت السوبر أدمن على Telegram وأرسل `/start` — يجب أن يرد عليك (لأن رقمك مطابق لـ
   `SUPER_ADMIN_TELEGRAM_ID`). أي شخص آخر يحاول استعمال هذا البوت يُتجاهل بصمت.
2. اضغط "➕ إضافة متجر جديد"، أدخل معرف Telegram لأول تاجر واسم متجره، واختر له باقة.
3. اطلب من التاجر يفتح بوت التاجر ويرسل `/start` — سيجد متجره جاهزًا مباشرة (بدون تسجيل ذاتي).
4. من بوت التاجر، اضغط "🔗 رابط متجرك للزبائن" للحصول على رابط `m.me/...?ref=...` الجاهز
   (يحتاج `FB_PAGE_USERNAME` مضبوطًا)، وشاركه مع التاجر ليضعه في صفحته/إعلاناته.

## لماذا 3 بوتات منفصلين، وليش الزبون بالذات صار فيسبوك؟

- **الزبون على فيسبوك**: لأن أغلب الزبائن فـ الجزائر يتفاعلون مع الإعلانات والمتاجر عبر فيسبوك
  مباشرة، فوضع بوت الطلبات هناك يقلل الاحتكاك (بلا حاجة يحمّل تليغرام).
- **التاجر والسوبر أدمن على تليغرام**: بلاصة تدار من هناك (بوت إدارة أسرع/أبسط تقنيًا، بلا حاجة
  webhook أو رابط عام).
- **عزل الأعطال**: لو صرا مشكل فـ بوت الزبائن (حمل عالي، تعطل فيسبوك)، بوت التاجر والسوبر أدمن
  يبقيان يعملان عاديًا.
- **أمان**: بوت السوبر أدمن معزول تمامًا، ومحمي بفحص هوية صارم (`SUPER_ADMIN_TELEGRAM_ID`).

## قبل الإطلاق التجاري - قائمة تحقق

- [ ] تجربة كاملة end-to-end: سوبر أدمن ينشئ متجر → تاجر يضيف منتج → زبون يطلب عبر ماسنجر → تاجر يستلم إشعار تليغرام
- [ ] تجربة كل باقة (المبتدئ/المحترف/الأعمال) والتأكد أن حدود الرسائل والمميزات تشتغل صح
- [ ] لو فعّلت `GROQ_API_KEY`: جرب رسالة صوتية وصورة من حساب زبون تجريبي على ماسنجر
- [ ] التأكد من إتمام App Review على فيسبوك (`docs/FACEBOOK_SETUP.md`) قبل مشاركة الروابط مع زبائن حقيقيين
      (وإلا فقط الحسابات المضافة كـ Testers تقدر تستعمل البوت)
- [ ] التأكد من Firestore Security Rules قبل ربط أي واجهة ويب لاحقًا
- [ ] إعداد نسخ احتياطي دوري لـ Firestore
- [ ] مراقبة اللوقات دوريًا (Railway → Logs tab لكل خدمة)
- [ ] ربط `SubscriptionService`/`StoreService.changePlan` بوسيلة دفع حقيقية لاحقًا (حاليًا التجديد يدوي من بوت السوبر أدمن)

## المراقبة (Monitoring)

النظام يكتب اللوقات لملفات محلية (`logs/`)، لكن على Railway الملفات المحلية تُمسح عند كل إعادة نشر.
**توصية**: راقب "Logs" tab في كل خدمة على Railway كمصدر أساسي، وفكر لاحقًا في خدمة تجميع لوقات خارجية.
