# مساعد الذكاء الاصطناعي والرد الصوتي

الجزء الثاني من خطة تحويل RedonBot (بعد `docs/DELIVERY_INTEGRATION.md`). يغطي هذا الملف
المتطلبات #7 (مساعد ذكاء اصطناعي حقيقي للتاجر)، #8 (رد ذكي على العملاء - جزء منه كان
موجودًا مسبقًا)، #14/#15 (نظام الردود الصوتية الذكي)، و#16 (إعدادات الذكاء الاصطناعي).

## البنية الجديدة

- `src/config/aiSettings.js` — الإعدادات الافتراضية + تعريف "طرق الرد" الأربعة (ذكي/دائمًا
  نص/دائمًا صوت/مخصص).
- `src/services/ai/TextToSpeechService.js` — يحوّل أي نص إلى ملف صوتي عربي طبيعي عبر Groq
  (نموذج Orpheus العربي)، ويخزّنه بشكل دائم عبر `VoiceBlobRepository` الموجود مسبقًا (نفس
  آلية الرسائل الصوتية المسجّلة يدويًا).
- `src/services/ai/AIReplyDeliveryService.js` — "المايسترو": يقرر لكل رد ديناميكي (تعلّم/AI/
  fallback) هل يُرسل نصًا أو صوتًا أو الاثنين، حسب `aiSettings.replyMode` ونوع رسالة الزبون
  الأصلية (نص أو صوت). إذا فشل توليد الصوت لأي سبب، يسقط تلقائيًا لرد نصي (لا يبقى الزبون بلا رد).
- `src/services/ai/AIAdvisorService.js` — مستشار التاجر: يجمع بيانات حقيقية من المتجر
  (`OrderService.getStats/getTopProducts`, `RatingService.getAverage`, `ProductService`)
  ويستعملها كسياق لأي سؤال حر ("ليش قل البيع؟") أو توليد محتوى (وصف منتج، منشور إعلاني،
  حملة Messenger/WhatsApp، رد مقترح، اقتراح خصم).

## ما تم ربطه بالنظام الحالي (بلا كسر أي شيء)

- الرسائل الصوتية **المسجّلة يدويًا من التاجر لكل نية** (`decisionEngine` + `VoiceNoteService`)
  بقيت كما هي تمامًا - لم تُلمس. هذا نظام منفصل ومختلف عن التوليد الديناميكي بالذكاء الاصطناعي.
- الردود **الديناميكية فقط** (رد من نظام التعلّم/الذاكرة، ترحيب المتجر، مدة التوصيل، الرد
  الافتراضي fallback، ورسالة "اسأل توضيحي") أصبحت تمر عبر `AIReplyDeliveryService.sendSmartReply`
  بدل `FacebookMessengerService.sendText` مباشرة - نفس النص المُرسل، فقط الوسيلة (نص/صوت)
  أصبحت قابلة للتحكم.
- رسالة الزبون الصوتية تُمرَّر الآن بعلامة `inputType: 'voice'` إلى `handleFreeText` (كانت
  تُحوَّل لنص وتُعامل كأنها نص عادي فقط).

## نقاط API الجديدة (`/api/dashboard/...`)

| Method | المسار | الوصف |
|---|---|---|
| GET | `/ai-settings` | إعدادات الذكاء الاصطناعي الحالية للمتجر |
| PUT | `/ai-settings` | تحديث الإعدادات (طريقة الرد، الصوت، الأسلوب...) |
| POST | `/ai/ask` | `{ question }` — سؤال حر للمستشار |
| POST | `/ai/generate` | `{ type, params }` — توليد محتوى تسويقي/وصف منتج |
| GET | `/ai/analyze/sales-drop` | تحليل جاهز لسبب انخفاض المبيعات |
| GET | `/ai/analyze/order-rejections` | تحليل جاهز لنسبة الطلبات الملغاة |

## متغيرات بيئة اختيارية جديدة

- `GROQ_TTS_MODEL` (افتراضي: `canopylabs/orpheus-arabic-saudi`)
- `GROQ_TTS_VOICE_MALE` (افتراضي: `abdullah`) و `GROQ_TTS_VOICE_MALE` (افتراضي: `aisha`)
- كلها تعتمد على `GROQ_API_KEY` الموجود مسبقًا - لا حاجة لمفتاح إضافي.

⚠️ **مهم**: تحقق من [توثيق Groq TTS الرسمي](https://console.groq.com/docs/text-to-speech)
قبل الإطلاق للتأكد من اسم النموذج/الأصوات الحالية (Groq تُحدّث أسماء النماذج من وقت لآخر
وتُوقف القديمة - حدث هذا سابقًا مع `playai-tts-arabic`).

## ما تبقّى

- **واجهة الاستخدام (Frontend)**: صفحة "إعدادات الذكاء الاصطناعي" + صفحة "المساعد" (شات
  للتاجر يسأل ويولّد محتوى) لم تُبنيا بعد - الـ API جاهز فقط.
- **تفعيل حسب الباقة**: الميزات الجديدة (المساعد، طرق الرد المتقدمة) غير مقيّدة بعد بالباقات
  - سيتم ضبطها فـ مرحلة "إعادة تصميم الباقات" (المتطلب #13، آخر مرحلة حسب الخطة الأصلية).
  حاليًا الرد الصوتي يبقى مقيّدًا فقط بـ `store.features.voiceReply` الموجود مسبقًا.
- **فهم الصور ضمن "الرد الذكي"** (تحليل الصور) كان موجودًا مسبقًا فـ `AIMediaService` ولم
  يتغيّر.
