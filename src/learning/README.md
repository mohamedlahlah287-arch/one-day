# نظام التعلّم والذاكرة (`src/learning`)

هذا المجلد يجمّع كل ميزات "التعلّم مع الوقت" المطلوبة: ذاكرة كل متجر، التعلّم من تعديلات
التاجر، دفتر القرارات، زر "علمني"، تنظيف الرسائل، فهم الأخطاء الإملائية والإيموجي، قاموس كل
متجر، نظام النوايا، والإحصائيات الأسبوعية.

## لماذا وحدة (Module) منفصلة بهذا الشكل؟

نفس فلسفة `docs/ARCHITECTURE.md`: كل ميزة فـ مجلدها الخاص، بملف Repository (وصول Firestore
فقط) وملف Service (منطق الأعمال) منفصلين. هذا يعني:

- تقدر تبدّل خوارزمية القاموس أو التطابق التقريبي بلا لمس دفتر القرارات أو الذاكرة.
- تقدر تضيف "مرحلة" جديدة لخط الأنابيب (مثال: تحليل مشاعر أدق) بلا كسر أي شيء آخر.
- كل خدمة قابلة للاختبار بمعزل (بلا Telegram ولا Facebook).

## خريطة المجلدات

| المجلد | المسؤولية |
|---|---|
| `normalization/` | تنظيف الرسالة: تكرار الأحرف، توحيد الحروف العربية، تصحيح أخطاء شائعة، مطابقة تقريبية (Levenshtein) |
| `emoji/` | فهم الإيموجي كإشارة نية أو مشاعر (💰 = سعر، 😡 = غاضب...) |
| `dictionary/` | قاموس كل متجر الخاص (كلمات محلية مثل "لافريزون" = التوصيل) - Repository + Service بتخزين مؤقت |
| `memory/` | ذاكرة أسلوب التاجر (عبارات متكررة) + معلومات حرة متعلَّمة |
| `decisions/` | دفتر قرارات التاجر - سؤال نموذجي مربوط بقرار ثابت، مع مطابقة تشابه (Jaccard) |
| `training/` | تسجيل كل تعديل/موافقة من التاجر كـ"مثال تعلّم"، ويوزّع التعلّم على الذاكرة والقاموس |
| `conversationLog/` | سجل كل دورة محادثة (رسالة + رد + مصدر الرد + حالة المراجعة) |
| `intent/` | **`intentResolver.js`** - المنسّق الرئيسي: يجمع كل المراحل قبل اللجوء لـ AI |
| `stats/` | بناء التقرير الأسبوعي (أكثر الأسئلة، ردود معدَّلة، كلمات/قرارات جديدة، اقتراحات) |
| `teach/` | زر "علمني" (✔ ممتاز / ✏️ تعديل): لوحة مفاتيح Telegram + معالجات + سيناريو التقاط التعديل |

## تدفق رسالة زبون واحدة (البند الثاني عشر فـ المتطلبات)

```
رسالة الزبون (Facebook Messenger)
      ↓
[مطابقة منتج مباشرة - موجودة سابقًا فـ catalogController]
      ↓ (لا تطابق)
intentResolver.resolve(storeId, message)
      │
      ├─ 1) normalization: تنظيف + تصحيح أخطاء شائعة
      ├─ 2) emojiIntent: تحليل الإيموجي
      ├─ 3) DecisionService: هل هذا سؤال له قرار ثابت محفوظ؟ → رد جاهز فورًا
      ├─ 4) بحث فـ ردود سابقة عدّلها التاجر لسؤال شبيه جدًا → رد جاهز فورًا
      ├─ 5) engine.detectIntent (كلمات مفتاحية تامة)
      ├─ 6) fuzzy intent matching (خطأ إملائي بحرف أو حرفين)
      ├─ 7) StoreDictionaryService.lookup (قاموس هذا المتجر تحديدًا)
      └─ 8) إشارة الإيموجي كخط دفاع أخير
      ↓ (لا شيء حُسم بعد)
AIMediaService.classifyIntent (إن كان مفعّلًا) - خط الدفاع الأخير
      ↓
catalogController يبني الرد (قالب جاهز حسب النية، أو AI، أو fallback)
      ↓
logTurn(): تسجيل فـ conversationLog + إرسال بطاقة "علمني" للتاجر إذا كان المصدر AI/fallback
```

## كيف يكتسب البوت "أسلوب التاجر" مع الوقت؟

عندما يضغط التاجر "✏ تعديل الرد" (`teach/teachHandlers.js`) ويكتب الرد الصحيح:

1. `TrainingService.recordEdit` يحفظ المثال الكامل (رسالة الزبون + رد AI + الرد النهائي).
2. `StoreMemoryService.learnFromMerchantEdit` يستخرج "عبارة افتتاحية" من الرد ويحفظها فـ ذاكرة
   المتجر (تُستعمل لاحقًا كسياق أسلوب - راجع `StoreMemoryService.buildStyleHint`).
3. إذا كانت رسالة الزبون تحتوي كلمة غير مفهومة، ورد التاجر يطابق نية معروفة، يتعلّم البوت
   تلقائيًا هذه الكلمة فـ قاموس المتجر (`StoreDictionaryService.learnTerm`).
4. `intentResolver` يبحث فـ هذه الأمثلة (`findSimilarPastReply`) لسؤال جديد شبيه جدًا مستقبلاً
   ويعيد استعمال نفس الرد النهائي مباشرة - هذا ما يجعل "البوت يكتب بنفس الأسلوب" بعد تكرار كافٍ.

التاجر يقدر أيضًا يحوّل أي تعديل لـ"قرار ثابت" مباشرة (زر "📒 نعم، احفظه كقرار ثابت" الذي
يظهر بعد كل تعديل) بدل انتظار تكرار السؤال عدة مرات.

## قيود معروفة (Trade-offs)

- **التخزين المؤقت (Cache) داخل العملية**: `StoreDictionaryService` و`DecisionService` يحتفظان
  بذاكرة مؤقتة (5 دقائق) لكل متجر لتفادي قراءة Firestore فـ كل رسالة. إذا شغّلت أكثر من نسخة
  (Instance) من نفس البوت، كل نسخة عندها ذاكرتها الخاصة (نفس القيد الموثّق فـ
  `docs/ARCHITECTURE.md` بخصوص eventBus والطابور) - مقبول للحجم الحالي، وينتقل لـ Redis
  لاحقًا بلا تعديل واجهة الاستعمال.
- **"فهم الأخطاء الإملائية"** هنا خوارزمية بسيطة (Levenshtein + تصحيحات شائعة يدوية)، وليست
  نموذج تصحيح إملائي كامل - كافية لأغلب أخطاء الكتابة السريعة، لكن ليست مثالية 100%.
- **بطاقة "علمني"** تُرسل فقط للردود القادمة من AI أو fallback (وليس كل رد) لتفادي إغراق
  التاجر بمراجعة كل "سلام" أو كل رد قالب جاهز - هذا قرار تصميم مقصود، قابل للتغيير من
  `catalogController.logTurn` (شرط `needsReview`) لو رغب التاجر بمراجعة كل شيء.

## نقطة الدخول الموصى بها

باقي المشروع يفضَّل يستورد من `src/learning/index.js` (barrel export) بدل الدخول لمسارات
داخلية مباشرة، حتى يبقى ممكنًا إعادة تنظيم أي وحدة داخلية بلا كسر كود خارجي.
